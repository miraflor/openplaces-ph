# OpenPlaces PH — September 2026 review (0.2.1)

This document records why 0.2.1 differs from 0.2.0. The executable contract lives in the code and the tests.

## Method

The 0.2.0 code was read in full and its 110 tests were run (all passed, DuckDB 1.5.5 with the spatial extension). Each suspected problem was then reproduced with small synthetic data or a local HTTP server before it was changed. Every fix has a test that fails on the 0.2.0 behaviour. The final suite (150 tests) passes on Python 3.11.15 and 3.12.3 with DuckDB 1.5.5.

The architecture was already careful: tiling, bounded DuckDB memory, Parquet checkpoints, the one-observation-per-source union-find, and the calibrated acceptance ladder. The review found no error in the blocking grid, the acceptance ladder, or the clustering; a new brute-force test now confirms the blocking and tiling on 475 accepted pairs. The serious problems were in one area: the stop/resume and refresh behaviour. The tests ran each stage inside one process, so they could not see failures that need two sessions.

## Findings and fixes

| # | Problem in 0.2.0 | Evidence | Fix in 0.2.1 |
|---|---|---|---|
| 1 | The OSM stage could not finish: `osmium tags-filter` wrote to a `.part` name without `-f pbf`. | Osmium 1.16: "Could not detect file format"; `test_osm_prepare.py`. | Explicit `-f pbf`; clean temporary names. |

## Behaviour changes users will notice

- `--refresh-sources` downloads a source again only when its release changed, and an interrupted refresh continues on the next run with or without the flag. It no longer implies `--rebuild-match`.
- The first match run after upgrading rebuilds all shards once, because 0.2.0 shards have no record of their source snapshot. Finalization rebuilds once as well (`finalize_version` 4).
- State problems end the CLI with an `ERROR:` paragraph that names the command to run.
- `summary.json` gains a `sources` key.

## Questions left open deliberately

These are product decisions, not defects, and 0.2.1 does not change them.

- **Non-Latin names.** Normalization keeps ASCII letters and digits only, so a name written only in Chinese, Korean, Arabic, or another non-Latin script becomes empty and the record is dropped, not kept as a single-source POI. Options: keep such records as unmatched observations, or match on a Unicode-aware normalization.
- **Mixed category vocabularies.** `canonical_category` falls back to the next source when the preferred source has no category, so one column mixes three taxonomies and can disagree with the source of `canonical_name`. A `canonical_category_source` column would make this explicit.
- **Name priority.** FSQ → Overture → OSM is a choice; for some areas OSM names may be the better display name. Worth measuring on the Metro Manila smoke test.
- **National extent.** `philippines_bbox` starts at 116.80°E, which excludes the Kalayaan municipality (Pag-asa Island is near 114.3°E).
- **Foursquare transfer size.** Each 1-degree query reads remote Parquet with `country = 'PH'` and coordinate filters. How many bytes each query transfers depends on how the upstream files are sorted and was not measured here; if it is large, one national `country = 'PH'` extract followed by local tiling may be cheaper.
- **Non-editable installs.** The CLI finds `config/` and `data/` relative to the source tree, which only works with `pip install -e .`.

## Not verified in this review

- Windows (the reference platform). The new code uses the same rename-based patterns as 0.2.0, but it was run only on Linux.
- Osmium ≥ 1.18 (the environment pin). The OSM test ran with Osmium 1.16; the format detection that broke the filter step is based on the file-name suffix in libosmium, which is not expected to differ. One command confirms it on your machine: `osmium tags-filter -t -o test.osm.pbf.part -O any.osm.pbf nwr/amenity` fails without `-f pbf`.
- Real upstream services (Geofabrik, Overture S3/STAC, Hugging Face). They were replaced by local fakes that follow their documented behaviour.
- Run time and memory at national scale.
