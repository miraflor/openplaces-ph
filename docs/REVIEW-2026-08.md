# OpenPlaces PH — August 2026 review and hardening notes

This document records why v0.2.0 differs from the initial public v0.1.0. It is
kept as engineering history; the executable contract lives in the code and tests.

## What was retained from v0.1.0

The original architecture was sound: nationwide processing is tiled, outputs are
points, work is checkpointed, DuckDB is constrained rather than allowed to claim
the whole machine, source provenance is preserved, and final clustering forbids
two observations from the same source in one entity. Those principles remain.

## Major v0.2.0 changes

1. **Blocking follows `--max-distance`.** The matching cell is derived from the
   search radius using a conservative Philippine longitude scale, so non-default
   radii cannot silently lose in-range pairs.
2. **Cheap bounds precede Haversine.** Latitude/longitude bounds discard impossible
   grid-neighbour candidates before trigonometry.
3. **One acceptance ladder.** SQL and the readable Python mirror are generated
   from the same piecewise calibration and parity-tested. Importantly, shortening
   the radius does not make the last partial interval stricter.
4. **The national sort is narrow.** Wide edge attributes stay in `edge_ids.parquet`;
   only `(left_id, right_id)` is sorted in `ranked_pairs.parquet`.
5. **Row IDs are streamed.** `file_row_number` replaces a national window operator.
6. **Union-find is actually compact in RAM.** The parent vector is `array('I')`
   (4 bytes per observation), with one-byte rank and source mask. A Python
   `list[int]` was rejected because it would defeat the 8 GB design target.
7. **Checkpoints are transactional and time-budgeted.** A hard interruption replays
   only work after the last committed snapshot.
8. **Overture coastal clipping is tolerant.** A small land tolerance avoids
   systematically deleting coastal/reclaimed places from one source only.
9. **CRS is explicit.** Geometry operations use `OGC:CRS84`; the final canonical
   file must contain GeoParquet metadata before it is promoted.
10. **Transitivity is visible.** `cluster_max_pair_distance_m` and
    `completed_transitively` expose triples held together without all three direct
    links.
11. **Accepted edges must resolve exactly.** Finalization checks for missing or
    duplicate source IDs instead of silently dropping/duplicating links.
12. **Large HTTP downloads are safer.** Partial bytes are resumed, length-checked,
    fsynced once per network attempt, and promoted only when complete.

## Why strict triangle closure is still not enforced

A three-source cluster can be produced by A↔B and B↔C even if A↔C was not accepted.
That is a recall/precision policy choice rather than an implementation error. v0.2.0
therefore measures it instead of silently changing the product. After a real run,
inspect `canonical_pois_completed_transitively` and the distribution of
`cluster_max_pair_distance_m` before deciding whether a future strict-closure mode
is justified.

## Verification before a nationwide run

Use this order:

```powershell
pytest -q
openplaces --areas metro_manila --only sources --temp-dir D:\openplaces-temp
openplaces --areas metro_manila --only match --temp-dir D:\openplaces-temp
openplaces --areas metro_manila --only finalize --temp-dir D:\openplaces-temp
```

Then inspect `data/output/areas_metro_manila/summary.json` and load
`canonical_pois.parquet` in QGIS before committing to the full Philippines run.
